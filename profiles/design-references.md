# Design and verification references

Use the upstream material relevant to the product. Before importing code, record the exact package or example, version, licence and asset attribution. The links here are references; paid examples, logos, photographs and fonts can have separate terms.

| Product surface | Official examples | Acceptance exercise |
| --- | --- | --- |
| SaaS dashboard and account pages | [shadcn/ui blocks](https://ui.shadcn.com/blocks) and [component docs](https://ui.shadcn.com/docs) | Exercise an empty account, long table, loading and failed request at desktop and phone widths. |
| Dialogs and menus | [Radix primitives](https://www.radix-ui.com/primitives) and [WAI interaction patterns](https://www.w3.org/WAI/ARIA/apg/patterns/) | Complete with keyboard only, close with Escape, restore focus. |
| Enterprise data workflows | [IBM Carbon patterns](https://carbondesignsystem.com/patterns/overview/) | Keep selection and focus coherent across filtering, errors and pagination. |
| Multi-step service forms | [GOV.UK patterns](https://design-system.service.gov.uk/patterns/) | Go back, edit an answer and recover from a validation error without losing input. |
| Motion and transitions | [Motion examples](https://motion.dev/examples) and [React docs](https://motion.dev/docs/react) | Interrupt an animation, repeat it and exercise reduced-motion preferences. |
| Workflow canvas | [React Flow examples](https://reactflow.dev/examples) | Drag, connect, delete, undo, reload and verify the saved graph. |
| Accessibility review | [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | Record criterion, browser, viewport, assistive technology and observed result. |
| Application defences | [OWASP ASVS](https://asvs.owasp.org/) | Select applicable requirements and bind each to tests and deployment evidence. |
